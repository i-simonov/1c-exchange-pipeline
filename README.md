# Конвейер обмена данными для 1С

`1c-exchange-pipeline` — ядро для декларативной регистрации объектов к обмену в 1С:Предприятии. Сценарий задает последовательность независимых обработчиков, а диспетчер собирает и выполняет ее для нужного объекта и плана обмена.

Ядро не содержит прикладных планов обмена, правил маршрутизации и транспорта. Готовый пример с тестовыми данными находится в репозитории [1c-exchange-pipeline-demo](https://github.com/i-simonov/1c-exchange-pipeline-demo). Для первого знакомства лучше начать именно с него: ядро уже включено в demo.

## Возможности

- декларативный реестр сценариев по объектам метаданных;
- цепочки обработчиков в стиле Filter → Router → Mapper → Output;
- общий контекст выполнения и менеджер временных таблиц;
- сохранение предыдущего состояния объекта перед записью;
- очередь связанных заданий в рамках одной регистрации;
- ручной пакетный запуск сценариев;
- точка переопределения встроенных обработок внешними обработками БСП.

## Требования

- платформа 1С:Предприятие 8.3.24 или новее;
- управляемое приложение;
- отдельная тестовая база для первого подключения и проверки.

Зависимости от БСП нет. Пример интеграции с подсистемой «Дополнительные отчеты и обработки» оставлен в исходниках закомментированным и включается только в конфигурациях, где уже есть БСП.

## Установка ядра

### Готовое расширение

1. Скачайте файл `pipeline_v1_0_0.cfe` из [релиза ядра](https://github.com/i-simonov/1c-exchange-pipeline/releases/tag/v1.0.0).
2. Сделайте резервную копию информационной базы.
3. Откройте базу в Конфигураторе и перейдите в **Конфигурация → Расширения конфигурации**.
4. Добавьте расширение из файла `pipeline_v1_0_0.cfe`.
5. Убедитесь, что расширение `КонвейерОбменаДанными` активно и не содержит ошибок проверки применимости.
6. Запустите 1С:Предприятие и проверьте журнал регистрации.

После этого установлено только ядро. До добавления прикладного плана обмена, реестра и обработчиков оно не регистрирует объекты и не отправляет данные.

> Не устанавливайте одновременно ядро и [demo-расширение](https://github.com/i-simonov/1c-exchange-pipeline-demo): demo уже содержит это ядро и предназначено для самостоятельной установки.

### Загрузка из исходников

Исходники расширения находятся в каталоге [`src`](src). Их можно загрузить в пустое расширение через **Конфигурация → Загрузить конфигурацию из файлов**.

Параметры расширения должны соответствовать поставке:

- имя — `КонвейерОбменаДанными`;
- назначение — `Адаптация` (`Customization`);
- префикс имен — `КОД_`;
- режим совместимости — `8.3.24`.

Для прикладного проекта используйте загруженное расширение как основу либо перенесите объекты ядра в собственное расширение/конфигурацию. Ниже перечислены обязательные точки интеграции.

## Подключение к прикладной конфигурации

### Шаг 1. Добавьте план обмена

Создайте или заимствуйте план обмена, узлы которого будут получателями сообщений. Ядро не навязывает состав реквизитов плана: условия маршрутизации определяет ваш обработчик Router.

Например, в demo используется `Демо_КОД_ОбменСайтом` с узлами `WEB`, `MARKET` и `B2B`.

### Шаг 2. Добавьте реестр сценариев для плана обмена

Скопируйте обработку-шаблон `КОД_РеестрСценариев_ИмяПланаОбмена`, переименуйте ее под свой план и реализуйте экспортную функцию `РеестрКонвейеровРегистрации()`.

Ключ соответствия — объект метаданных, значение — массив сценариев. Каждый сценарий содержит:

- `Конвейер` — обработку, которая собирает и запускает цепочку;
- `Обработчики` — упорядоченный массив обработок этапов;
- `КодыУзлов` — необязательное ограничение по кодам узлов; пустой массив означает, что ограничение задаст маршрутизатор.

```bsl
Функция РеестрКонвейеровРегистрации() Экспорт

	РеестрСценариев = Новый Соответствие;
	СценарииЗаказов = Новый Массив;
	СценарииЗаказов.Добавить(СценарийРегистрацииЗаказов());
	РеестрСценариев[Метаданные.Документы.ЗаказКлиента] = СценарииЗаказов;

	Возврат РеестрСценариев;

КонецФункции

Функция СценарийРегистрацииЗаказов()

	Обработчики = Новый Массив;
	Обработчики.Добавить(Метаданные.Обработки.МойФильтрЗаказов);
	Обработчики.Добавить(Метаданные.Обработки.МойМаршрутизаторЗаказов);
	Обработчики.Добавить(Метаданные.Обработки.МоиЗаказыВJSON);
	Обработчики.Добавить(Метаданные.Обработки.МойВыходВОчередь);

	Сценарий = Новый Структура;
	Сценарий.Вставить("Конвейер", Метаданные.Обработки.КОД_КонвейерОбработчиковБазовый);
	Сценарий.Вставить("Обработчики", Обработчики);
	Сценарий.Вставить("КодыУзлов", Новый Массив);

	Возврат Новый ФиксированнаяСтруктура(Сценарий);

КонецФункции
```

### Шаг 3. Добавьте обработчики конвейера

Каждый этап создается как обработка с двумя экспортными методами:

- `Следующий(Обработчик = Неопределено)` — устанавливает или возвращает следующий элемент цепочки;
- `Обработать(Контекст, Вход = Неопределено)` — выполняет свою ответственность и передает управление дальше.

Минимальный каркас:

```bsl
Перем СледующийОбработчик;

Функция Следующий(Обработчик = Неопределено) Экспорт
	Если Обработчик <> Неопределено Тогда
		СледующийОбработчик = Обработчик;
	КонецЕсли;
	Возврат СледующийОбработчик;
КонецФункции

Процедура Обработать(Контекст, Вход = Неопределено) Экспорт

	// Логика текущего этапа.

	Если СледующийОбработчик <> Неопределено Тогда
		СледующийОбработчик.Обработать(Контекст, Вход);
	КонецЕсли;

КонецПроцедуры
```

Рекомендуемое разделение ответственности:

1. **Filter** отбирает изменившиеся и допустимые объекты.
2. **Router** сопоставляет объектам узлы-получатели.
3. **Mapper** формирует тело и заголовки сообщения.
4. **Output** сохраняет сообщение в очередь или передает его транспортному слою.

Контекст содержит исходные ссылки в `Контекст.Вход`, сведения о запуске и менеджер временных таблиц в `Контекст.Выполнение`, а также общие изменяемые данные в `Контекст.Данные`. Рабочие временные таблицы должны создаваться через общий `Контекст.Выполнение.МенеджерВременныхТаблиц`.

Полные реализации обработчиков и их контрактов смотрите в [demo-репозитории](https://github.com/i-simonov/1c-exchange-pipeline-demo/tree/main/src/DataProcessors).

### Шаг 4. Свяжите план обмена с реестром

В общем модуле `КОД_ДиспетчерРегистрацииКОбменуПереопределяемый` заполните процедуру `РеестрыСценариевПоПланамОбмена`:

```bsl
Процедура РеестрыСценариевПоПланамОбмена(РеестрыПоПланамОбмена) Экспорт

	РеестрыПоПланамОбмена[Метаданные.ПланыОбмена.МойПланОбмена] =
		Метаданные.Обработки.МойРеестрСценариев;

КонецПроцедуры
```

Для каждого плана обмена указывается отдельная обработка-реестр. Один объект метаданных может иметь несколько сценариев внутри одного реестра.

### Шаг 5. Добавьте точку запуска регистрации

Для ссылочных объектов можно создать две подписки на события:

| Подписка | Событие | Обработчик |
| --- | --- | --- |
| Перед записью | `ПередЗаписью` | `КОД_ПодпискиНаСобытияПереопределяемый.ОбменПередЗаписьюДокументы` |
| После записи | `ПриЗаписи` | `КОД_ПодпискиНаСобытияПереопределяемый.ОбменПриЗаписиДокументы` |

В источники подписок включайте только документы, перечисленные в реестрах сценариев. Первая подписка сохраняет предыдущую версию в `ВТ_ПредыдущаяВерсия`, вторая запускает регистрацию уже записанной ссылки.

Для справочников, регламентного задания, команды или другого события вызовите диспетчер напрямую:

```bsl
Ссылки = Новый Массив;
Ссылки.Добавить(СсылкаОбъекта);

КОД_ДиспетчерРегистрацииКОбмену.ЗарегистрироватьПоРееструСценариев(
	Метаданные.Справочники.Номенклатура,
	Ссылки);
```

Если обработчику нужна предыдущая версия, до записи создайте менеджер методом `СоздатьМенеджерВременныхТаблицПредыдущейВерсииУниверсальный()` и передайте тот же экземпляр третьим параметром в `ЗарегистрироватьПоРееструСценариев()`.

Чтобы временно отключить автоматическую регистрацию конкретного объекта, перед записью установите:

```bsl
Объект.ДополнительныеСвойства.Вставить(
	"ОтключитьМеханизмРегистрацииОбъектов",
	Истина);
```

### Шаг 6. Реализуйте выход и доставку

Ядро заканчивается на выполнении цепочки. Добавьте собственный Output-обработчик, который сохраняет подготовленные сообщения в регистр, очередь сообщений или другой надежный буфер.

Повторные попытки, идемпотентность, подтверждения, порядок доставки и очередь ошибок относятся к транспортному слою и в ядро не входят.

### Шаг 7. Проверьте интеграцию

1. Обновите конфигурацию базы данных и перезапустите 1С:Предприятие.
2. Создайте узлы плана обмена, на которые рассчитывает Router.
3. Измените объект, включенный в реестр и подписки.
4. Проверьте прохождение Filter → Router → Mapper → Output.
5. Проверьте повторную запись без изменений, смену маршрута и пакетный запуск.
6. Убедитесь, что ошибка обработчика не оставляет частично подготовленные данные в вашей постоянной очереди.

## Состав ядра

| Объект | Назначение |
| --- | --- |
| `КОД_ДиспетчерРегистрацииКОбмену` | Запуск сценариев, очередь связанных заданий и общий контекст регистрации |
| `КОД_КонвейерОбработчиковБазовый` | Сборка и выполнение цепочки обработчиков |
| `КОД_РеестрСценариев_ИмяПланаОбмена` | Копируемый шаблон реестра сценариев |
| `КОД_ПодпискиНаСобытияПереопределяемый` | Готовые обработчики подписок для документов |
| `КОД_ДиспетчерРегистрацииКОбменуПереопределяемый` | Привязка планов к реестрам и необязательная интеграция с БСП |
| `КОД_РучнаяРегистрация` | Ручной пакетный запуск сценариев (драфт) |

## Ограничения версии 1.0.0

- снимок предыдущего состояния включает стандартные и обычные реквизиты, но не табличные части;
- готовые автоматические подписки реализованы для документов; другие типы объектов подключаются отдельно;
- транспорт и эксплуатационные гарантии доставки не входят в поставку;
- обработка ручной регистрации имеет статус draft;
- закомментированный код интеграции с БСП нужно адаптировать к версии библиотеки в целевой конфигурации.
